## First thing to run

```sh
uv run --group dev pytest -q
```

Expect **223 passed**. Do this **before touching any PLC toolchain.** It is the
cheap check, and it says the environment is sane before something harder fails.
A toolchain problem and a program problem look identical when you meet them
together.

If `uv` is missing: `winget install --id=astral-sh.uv -e`

The full sequence for bringing the control program up on a runtime, including a

## Two things to keep straight

**`plc/io_declarations.st` is generated. Never hand edit it.** If an address
changes, change the enum in `src/vpc/process_image.py` and regenerate:

```sh
uv run python -c "from vpc.process_image import structured_text_declarations; print(structured_text_declarations())" > plc/io_declarations.st
uv run --group dev pytest -q tests/test_st_matches_the_model.py
```

The address map exists once, on purpose. Two copies of an address map is one
copy plus a future defect.

**`src/vpc/packml.py` is the authority, not the Structured Text.** The Python
model is verified exhaustively and the ST implements it. If the two disagree,
**the ST is wrong.** `tests/test_st_matches_the_model.py` parses the ST and
checks it.

## What is not built, so you do not go looking for it

- **No real hardware PLC.** It runs on a SoftPLC. A hardware target, or the
  CODESYS Linux runtime on the machine where the plant already lives, is the
  next step and the one that would matter most.
- **No hardware safety relay.** The safety channel is the P2 protection layer
  over the process image, not a certified device on a safety bus.
- **The OPC UA server uses a self-signed certificate.** Security is
  Basic256Sha256 sign-and-encrypt with anonymous access refused, which is the
  right posture, but a real deployment needs a real PKI.

## The constraint that shaped all of this

The PLC runtimes worth using are Windows only to author. So the project is
split: the plant, the state model, the Modbus layer and the tests are built and
**executed** on Linux, and only the Structured Text crosses.

That is not a workaround. It is how a virtual commissioning rig is normally
arranged, with the controller on its own runtime and the plant model elsewhere.
It is also why the Modbus layer was implemented rather than imported, and why
the PackML model exists in Python first: anything that cannot be executed has to
be checked some other way, and the cheapest other way is to keep the untestable
surface small and put a parser on it.
